시안 6·7·8·9를 합친 판으로 어드민 "기능 스위치" 화면을 정합니다. 데이터는 devbox 개발 DB(KR 149개, 2026-10-23 조회)이며 운영 값이 아닙니다. 점선 밑줄은 새 문구 초안입니다.

  • 한국어 이름(label)·depends_on·보관(archived_at) 칸은 3단계 마이그레이션, 실행은 승인 뒤

A디자인 — 실제로 동작하는 합본 화면

검색, 요약 숫자, 탭 3개, 상세 패널이 모두 동작합니다. 빨간 "꺼짐인데 나가는 중" 카드를 누르면 아래 B1 문제가 바로 보입니다.

6 정리함7 요약 + 최근 변경8 검색 한 칸9 함께 켜는 묶음
A1. 처음 열었을 때 보이는 탭
정리함은 정리가 끝나면 비는 일회성 목록이다. 평소 쓰는 화면은 묶음별 전체이고, 정리함 개수는 탭 옆 숫자로 남긴다.
A2. 목록에 보이는 한국어 제목은 어디서 오나
지금은 설명 앞부분을 잘라 쓴다. 영어 설명 플래그는 제목이 영어로 나오고, 잘린 결과가 어색할 때가 있다(예: "결제·오퍼 엔진…"). 별도 칸을 두면 3단계 마이그레이션이 필요하다.
A3. 일본(JP) 플래그는 어떻게 보나
시안 10(나란히 비교)은 고르지 않았다. 지금은 상단 국가 전환으로 따로 본다. 일본 플래그는 116개이고 한국과 이름이 다른 것이 섞여 있다.

B운영 규칙 — 끄면 정말 꺼지는가

이 화면의 핵심 가치는 "끄면 꺼진다"는 믿음입니다. 지금 서버는 스위치가 꺼져 있어도 다른 경로로 기능을 내보내고, 어드민 화면은 그 경로를 보여 주지 않습니다.

꺼짐 27개 중 14개가 실제로는 나가는 중 (devbox). evaluateFlagForUser(solo-nestjs-api src/feature-flags/services/feature-flags.service.ts:40)는 지정 유저 → 테스트 계정 → rollout_percentage 를 enabled 보다 먼저 본다. 어드민 토글(src/admin/v2/feature-flags/feature-flags-v2.service.ts:29)은 enabled 만 바꾼다. 그래서 live-female-routing·live-female-rank-guard·iap_72h_offer_enabled 는 꺼짐인데 롤아웃 100%로 로그인한 전원에게 켜져 있다. 운영 DB 값은 아직 확인하지 않았다.
B1. 스위치를 끄면 무엇까지 끄나
전부 끄면 QA 중인 테스트 계정도 못 본다. 일반 유저 경로(enabled·롤아웃)만 끄고 테스트 계정·지정 유저는 남기면, 실제 유저는 확실히 꺼지고 확인창에 "테스트 계정 유지"라고 적는다.
철회: 롤아웃 % 슬라이더(0~100 조절) — 일부 유저에게만 나눠 켜는 도구라 메모리 no-ab-experiments(분할 배정 제안 금지)에 걸린다. 롤아웃 값은 보여만 주고 편집하지 않는다. 현재 데이터도 0과 100만 있다.
B2. "함께 켜는 묶음" 관계는 어디서 오나
지금 시안은 설명 글자에서 다른 플래그 이름을 찾아 추정한다. 그 결과 8건 중 moment → love-exam-v1("moment inline menu"라는 영어 단어)처럼 잘못 묶인 것이 있다.
B3. 부모가 꺼진 상태에서 자식을 켜면
코드에서 부모와 AND로 묶이는지는 플래그마다 다르다(persona-twin-voice-coach 는 설명에 AND 명시, 다른 것은 불명). 막으면 정상적인 선오픈까지 막는다.
B4. 누가 언제 바꿨는지 기록
admin_action_logs(src/database/schema/admin_action_logs.ts, 변경 전후 diff 칸 있음)가 이미 있지만 플래그 서비스는 기록하지 않는다. 기록하면 "최근 변경" 탭에 관리자 이름과 변경 전후가 나온다.
B5. "폐기" 표기된 플래그 처리
행을 지우면 서버는 플래그가 없을 때 false로 읽어서 동작은 같지만(feature-flags.service.ts 의 if (!flag) return false), 설명과 이력이 함께 사라진다.

D전체 화면 설계

어드민 데스크톱 화면이라 휴대폰 틀 대신 상태별 패널로 그렸습니다.

① 불러오는 중

요약 숫자 5칸은 회색 자리, 목록에 스피너 하나. 기존 Spinner aria-label="불러오는 중" 유지.

② 검색 결과 없음

"검색어" 와 맞는 기능이 없습니다 + 검색어 지우기 버튼.

③ 정리함 0개

정리할 플래그가 없습니다. 탭 옆 숫자도 사라진다.

④ 확인창 · 저장 중

버튼 비활성, 바깥 클릭·Esc로 닫히지 않음(DESIGN.md 규칙). 끄기면 테스트 계정 N개는 계속 봅니다 한 줄.

⑤ 토글 실패

스위치 원래대로 + 토스트 "이름" 토글에 실패했습니다.(현재 문구 그대로, feature-flags-v2.tsx).

⑥ 꺼짐인데 나가는 중

목록 점 빨강, 상세 패널 빨간 상자에 받는 사람 목록 + 스위치는 꺼져 있지만 위 사람들에게는 켜져 있습니다.

⑦ 부모가 꺼짐

자식 행 아래 부모 "이름" 가 꺼져 있음 칩. 저장은 막지 않음(B3).

⑧ 작업 중 로그인이 풀림

지금은 refresh 실패 즉시 쿠키를 지우고 로그인 화면으로 보낸다. 쓰던 설명이 사라진다. 4단계에서 고친다.

어드민 화면이 대상 칸을 버림. 목록 API는 select() 로 모든 칸을 내려주는데 Project-Solo app/services/admin/feature-flags.ts:3 타입에 allowTestUsers·allowedUserIds·rolloutPercentage 가 없다. 그래서 지금 화면의 "전체 공개"는 사실과 다를 수 있다. 1단계는 타입만 늘리면 된다.
로그인이 풀리는 구조. refresh 토큰을 계정당 한 칸(users.refresh_token)에만 저장하고 갱신할 때마다 바꾼다(src/auth/services/auth.service.ts:441). 같은 계정으로 다른 곳에서 로그인하거나 탭·서버 인스턴스 두 곳이 동시에 갱신하면 한쪽 토큰이 무효가 되고, 어드민은 그 즉시 쿠키를 지운다(app/api/admin-proxy/[...path]/route.ts:127). 또 쿠키는 로그인 시점부터 30일 고정이라(shared/auth/session-config.ts:6) 30일째에는 무조건 풀린다. 로그로 어느 쪽인지 아직 확인하지 않았다.
D1. 로그인 유지 고치는 방향
서버 쪽은 마이그레이션이 필요하고 실행에는 별도 승인이 필요하다. 어드민 쪽만 고치면 동시 갱신 경합은 줄지만, 같은 계정을 여러 명이 쓰면 계속 풀린다.
